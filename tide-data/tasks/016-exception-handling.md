# 任务 016 — 异常场景处理 — 中断按钮 + 失败重试 + 会话恢复提示

**Epic:** 前端页面开发
**优先级:** P0
**关联需求:** FR-11, FR-12, FR-13

---

## 描述

实现三个异常场景的前端处理机制：用户主动中断 AI 响应、API 调用失败时重试、页面关闭后重新进入时恢复会话。

## 场景一：中断按钮

### 实现方式
- AI 响应过程中，输入框旁边或消息列表顶部显示"中断"按钮
- 点击后发送 `POST /api/sessions/:id/agent/cancel`
- 按钮变为"已中断"状态
- 消息列表中插入系统提示"用户已中断"

### 触发条件
- SDK 正在处理中（`tool_in_progress` 或 `streaming` 状态）
- 按钮只在 SDK 处理中显示

## 场景二：API 调用失败重试

### 实现方式
- SSE 连接异常或收到 `event: error` 时，消息列表中显示：
  ```
  ⚠️ AI 服务异常，请稍后重试
  [重新生成] 按钮
  ```
- 点击"重新生成"重新触发该轮请求
- 保留用户已发送的消息上下文

### 触发条件
- DeepSeek API 返回错误
- SSE 连接断开
- Token 过期

## 场景三：会话恢复提示

### 实现方式
- 进入一个已有未完成讨论的会话时，调用 `GET /api/sessions/:id/state`
- 如果 `canResume = true`，显示 Dialog：
  ```
  检测到未完成的需求讨论
  上次讨论时间：2026-07-22 14:30
  
  [🔄 恢复讨论]  [🆕 重新开始]
  ```
- 选择"恢复讨论"→ 加载上次的上下文，SDK 继续执行
- 选择"重新开始"→ 清除上下文，重新启动 Tide-discuss

### 触发条件
- 会话 status 为 active 且 context 非空

## 验收标准

- [ ] AI 处理中显示中断按钮，点击后停止响应
- [ ] API 失败时显示错误提示和重试按钮
- [ ] 重新进入未完成会话时弹出恢复 Dialog
- [ ] 恢复后可继续之前的讨论

## 技术要点

- 中断通过 Agent Module 的 cancel 接口实现
- 重试时复用已发送的最后一条用户消息
- 恢复状态通过 session context 中的 tide-discuss 阶段信息判断
