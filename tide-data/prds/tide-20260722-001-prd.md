## 7. 技术方案

### 7.1 架构概览

**架构模式：** 后端 NestJS 作为 Claude Agent SDK（TypeScript）host 进程，SDK 直接执行 Tide-discuss 工作流

**后端模块划分：**

| 模块 | 职责 |
|------|------|
| Auth Module | 测试账号登录（写死账号，JWT Token） |
| Project Module | 项目 CRUD |
| Session Module | 会话管理 + 历史列表 + **删除**（v1.1：归档→删除，级联清理 DB + JSONL 文件） |
| Chat Module | 消息收发 + SSE 流式推送（SDK 驱动内容，**v1.1：消息由 SDK JSONL 管理**） |
| Agent Module | 封装 Claude Agent SDK（TypeScript），加载 Skill，SessionStore 配置，自动启动讨论 |
| Asset Module | 资产面板展示（PRD 文档 + 关联的 Jira 任务等） |

### 7.2 数据库设计（v1.1 混合存储架构）

**核心理念：** 数据库仅存映射关系，完整消息内容由 SDK JSONL 管理。

#### 表结构

**users（测试用户）**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| username | String | 测试账号（写死） |
| password | String | 加密存储 |
| displayName | String | 显示名称 |
| createdAt | DateTime | 创建时间 |

**projects（项目）**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| name | String | 项目名称 |
| description | String? | 备注（可选） |
| createdBy | UUID → users.id | 创建者 |
| createdAt | DateTime | 创建时间 |
| updatedAt | DateTime | 更新时间 |

**sessions（会话）— v1.1 极简化**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键（与 SDK sessionId 保持一致） |
| projectId | UUID → projects.id | 所属项目 |
| title | String | 会话标题（可重命名） |
| filePath | String | 指向 SDK JSONL 文件的路径 |
| createdAt | DateTime | 创建时间 |
| updatedAt | DateTime | 更新时间 |

> **v1.1 移除字段：** `status`（归档取消，删除即物理删除），`context`（SDK 管理会话恢复）

**assets（资产）— v1.1 扩展**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| sessionId | UUID → sessions.id | 所属会话 |
| type | Enum | prd / jira_task / ... |
| title | String | 资产标题 |
| content | Text | 资产内容（Markdown / JSON） |
| metadata | JSON? | 额外元数据（如任务链接等） |
| createdAt | DateTime | 创建时间 |

#### 数据流示意

```
用户发送消息
  → POST /api/sessions/:id/messages
    → NestJS 转发给 Agent SDK
      → SDK 调用 AI 模型（DeepSeek/国产模型）
      → SDK 自动写入 JSONL（~/.claude/projects/...）
      → SDK 事件 → SSE → 前端渲染

读取历史消息
  → GET /api/sessions/:id/messages
    → SDK getSessionMessages(sessionId) 从 JSONL 读取
```

### 7.3 Claude Agent SDK 环境配置（v1.1）

| 项 | 决定 | 说明 |

## 8. UX 设计建议

**布局：** 三栏布局，左侧会话历史（可折叠）、中间聊天+输入框、右侧资产面板（可折叠）

**交互流程：**
1. 登录 → 项目列表
2. 创建项目（名称+备注）→ 自动进入项目
3. 项目内自动创建新会话 → 自动启动 Tide-discuss → 看到 Mary 介绍
4. 用户回复 → SDK 处理 → SSE 流式渲染（内容由 SDK 驱动）
5. 讨论完成 → PRD 出现在资产面板
6. 中断/异常时展示对应状态

**交互细节：**
- AI 运行中：文字提示状态（"正在分析需求…""正在生成 PRD…"），不用进度条
- SDK 确认：展示选项按钮 + "其他"按钮允许自由输入
- 会话历史：按时间倒序，用户可手动**删除**（级联清理 DB 记录 + SDK JSONL 文件，需二次确认）。v1.1：原归档改为删除
- 登录后直接进项目列表，无需中间首页/工作台
- 异常时：聊天框显示"AI 服务异常，请重试"+ 重试按钮
- 恢复：重新进入会话时提示"检测到未完成的会话，是否恢复？"（由 SDK resume 支持）

**设计约束：** PrimeNG 默认风格，不做定制化设计
