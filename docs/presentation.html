技术选型

技术架构的底层逻辑 Harness Agent vs LangGraph — 两条路线的本质区别

🔄 Harness Agent（我们的选择）

  • ✅ Harness Agent 运行时自主决策，流程不写死
  • ✅ Skills 是行为指令文档，动态加载按需消费
  • ✅ 每个任务独立的 agent 循环：思考→调工具→观察→再思考
  • ✅ 适合需求讨论、问题诊断等流程不确定的开放型任务
  • ✅ 代表：Claude Agent SDK

📋 LangGraph / Pipeline

  • ✗ 流程编码时固化为 DAG，A→B→C→D 不变
  • ✗ 工具是原子函数，需手动定义 schema 注册
  • ✗ 任务是流水线：走到哪步预先确定
  • ✗ 适合数据清洗、文档批处理等流程确定的任务
  • ✗ 代表：LangChain LangGraph

❓ 需求讨论无固定流程

想法诊断可能往任何方向走——市场分析、技术可行性、竞品对比。无法预画 DAG 覆盖所有路径。

📜 Skills 是核心资产

Skill 是行为指令文档而非代码。只有 Harness Agent 的设计能原生消费这种指令。

🧵 多角色互动是动态的

BMAD 中 Boss/Manager/Architect/Developer 的互动取决于进展，不是固定顺序。

选择市面上已有的方案

我们是业务团队，核心价值在于理解业务场景、沉淀业务 Skill。
Claude Agent SDK 已处理好——tool_use 循环、流式事件、MCP 协议、上下文管理、权限控制、Session 管理——这些是 引擎通用能力，不是我们的壁垒，Skill 才是。
站在成熟 SDK 之上聚焦业务，而非从零搭基础设施。

四个架构原则

1

SDK 黑盒

Agent 循环是 SDK 内部实现。Oceanus 只观察、不介入。SDK 升级不影响平台。

2

项目隔离

每个项目独立目录，SDK 通过 cwd 实现天然隔离。不引入容器，降低复杂度。

3

SSE 直通

流事件 → RxJS Subject → SSE → 浏览器。中间不缓存不转写，保留原始执行过程。

4

Skill 即资产

核心积累不是代码，是持续沉淀的 Skill 库。知识、流程最终体现为 SKILL.md。

能力扩展

流程

一次对话的完整流程 从用户输入到结果展示

  1. 用户发送消息
    Angular → POST /api/v1/chat → Controller
  2. Oceanus 准备执行环境
    SessionManager 加载历史 → 确定项目 cwd → 列出可用 Skill → 配置 MCP Server
  3. SDK.query() 启动 Agent 循环
    传入上下文，SDK 自动完成 Context 组装 + Model 选择，进入 tool_use 循环
  4. Agent 内部循环（SDK 黑盒）
    识别 Skill → 加载 SKILL.md → 按指令执行 → 调工具/MCP → 分析结果 → 继续或完成
  5. SSE Bridge 实时转发
    stream_event → RxJS Subject → SSE Endpoint → 浏览器 EventSource → UI 实时渲染
  6. Agent 返回最终结果
    structured_output + 文件产物 → AssetExtractor 提取资产 → 写入数据库
  7. 前端展示完成
    最终回复 + 资产列表 + 本次对话成本

关键设计：Oceanus 不介入 Agent 的决策循环。平台只在两端做事——启动前准备上下文，执行中监听事件流。SDK 升级完全不影响平台。
